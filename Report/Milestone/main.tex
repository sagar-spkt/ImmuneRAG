\begin{abstract}
Indirect prompt injection is a major security risk for retrieval-augmented generation (RAG) systems because attacker instructions hidden in retrieved content can override intended model behavior. To tackle this challenge, we present a implementation of an instruction-hierarchy training data generation pipeline for open-source language models, enforcing the policy that prioritize system instruction over user instruction over retrieved/tool content. The pipeline is implemented end-to-end with synthetic hierarchy case generation, quality filtering, and aligned/misaligned case balancing for capability retention, producing 5,249 final training/evaluation examples. To retain naturalness and authenticity of attack, data synthesis pipeline uses existing alignment dataset and adversarial prompt dataset as seed sets. Preliminary analysis indicates strong scenario coverage, near-balanced aligned/misaligned mixtures, and robust rendering quality suitable for finetuning. The remaining work will focuses on model finetuning and evaluation; we expect a measurable reduction in attack success rate while preserving benign task-following behavior.
\end{abstract}

\section{Introduction and Problem Statement}
Retrieval-Augmented Generation (RAG) is a practical standard for deploying large language models (LLMs) in enterprise and assistant settings. However, it introduces an important security vulnerability: indirect prompt injection. In this attack model, malicious instructions are embedded inside third-party content such as emails, web pages, or retrieved passages. Because most instruction-tuned models process all context tokens with similar semantic priority, they can confuse untrusted retrieved text with trusted instructions and execute attacker intent.

Traditional mitigations based on keyword filtering or pattern matching are brittle against paraphrase and adaptive attacks. Instruction hierarchy proposes a more structural defense. When instructions conflict, the model should follow privileged instructions first and treat lower-privilege content as data rather than authority \cite{wallace2024instructionhierarchytrainingllms}. This project investigates that principle in an open-source setting, targeting robust behavior under indirect injection while preserving normal instruction following.

Our instruction hierarchy data generation and training follows following approaches. We pair aligned instruction-following data with adversarial prompt-injection data to preserve utility while exposing realistic attacks; we use a staged pipeline adapting LLM to generate instruction hierarchy triplets and template to handle LLM failure cases in generation; we plan to finetune and evaluate an instruction-tuned open model to make instruction hierarchy learning.

The project has three major contributions. First, we develop a instruction hierarchy data generation pipeline that combines aligned and adversarial seeds, then synthesizes cases for both context synthesis (aligned) and context ignorance (misaligned). Second, we define a practical finetuning so hierarchy supervision can be learned efficiently without full-model retraining. Third, we establish an evaluation plan that jointly measures attack success rate, system-extraction leakage, over-refusal on benign prompts, and aligned-constraint adherence, enabling a balanced assessment of robustness and usability.

Here, we report completion of the full data pipeline and present quantitative evidence that the generated corpus is balanced, diverse, and ready for finetuning and evaluation in the next phase.

\section{Related Work}
Instruction hierarchy formalizes privileged instruction following under conflicting context and provides a training objective that separates aligned constraint-following instruction from misaligned instruction \cite{wallace2024instructionhierarchytrainingllms}. Recent attack work established that prompt-level manipulations can reliably induce policy violations in language models \cite{perez2022ignoreprevious}. 

For indirect prompt injection, BIPIA introduced task-grounded benchmarking with injected external content, highlighting that RAG systems require evaluation beyond direct jailbreak prompts \cite{yi2023bipia}. In parallel, structured-query training approaches such as StruQ show that explicit separation between instruction channels and untrusted text improves robustness under instruction conflicts \cite{chen2024struq}. Our work is aligned with these directions but emphasizes a practical, reproducible open-source implementation pipeline spanning data construction, finetuning, and evaluation.


\section{Methodology}
The first phase implements a five-stage sequential pipeline (Figure~\ref{fig:pipeline}) to construct instruction-hierarchy supervision at scale. We select aligned datasets (e.g., OASST2 and UltraChat) to retain broad instruction-following capability and language diversity, and adversarial datasets (e.g., HackAPrompt, Gandalf variants, LLMail, and prompt-injection corpora) to capture realistic override, extraction, and indirect-injection behaviors observed in practice.

Each stage has a compact operational role. Stage A aggregates raw aligned and adversarial records (example: an instruction-following dialogue and an injected email sample). Stage B converts heterogeneous schemas into a canonical seed with prompt, response, and metadata fields (example: role-tagged turns mapped into a unified prompt--response pair). Stage C generates instruction hierarchy cases with privileged system/user/tool structure (example: a summarization request where injected text asks to reveal hidden instructions, and the assistant refuses the malicious part while completing the summary). Stage D removes duplicates, filters malformed or low-quality records, enforces deterministic train/test splits, and rebalances aligned versus misaligned cases. Stage E renders finalized conversations into the target chat text format for supervised finetuning.

Stage C covers six scenarios of instruction hierarchy with distinct purposes: \texttt{sys\_extract\_misaligned} (refuse attempts to reveal higher-privilege instructions), \texttt{sys\_probe\_aligned} (answer benign system capability questions safely), \texttt{open\_misaligned} (ignore direct user-level override attacks), \texttt{open\_aligned} (compose response from non-conflicting system and user instructions), \texttt{closed domain misaligned} (treat injected strings inside task data as untrusted content), and \texttt{tool\_output\_misaligned} (ignore malicious directives embedded in tool outputs from RAG while using useful evidence).

To improve diversity, Stage C uses LLM-based synthesis to generate varied system/user/assistant triplets per scenario. Because LLM outputs can be malformed or incomplete, a deterministic template fallback is triggered on parse or validation failure; this guarantees full scenario coverage and stable throughput while preserving the intended hierarchy labels.

For the remaining experimental phase, finetuning will use QLoRA with 4-bit quantization on Llama and Qwen models, and evaluation will report attack success rate (misaligned), extraction rate, over-refusal (aligned), and aligned constraint adherence.

These results indicate that dataset composition is close to target proportions and retains broad scenario coverage after filtering. The aligned/misaligned balance is preserved in both train and test splits, supporting downstream robustness evaluation without severe class skew.

Failure analysis shows that most LLM synthesis failures are formatting-related rather than semantic collapse. Representative failure patterns include malformed strings with raw line breaks inside JSON fields, truncated records with unterminated quotes, and invalid backslash escapes (e.g., unsupported escaped characters). The template fallback strategy successfully mitigated these issues by preserving scenario completion despite generation-time parse failures.

\section{Conclusion}
This project establishes an instruction-hierarchy data pipeline for indirect prompt injection defense in RAG. The resulting corpus is balanced across aligned and misaligned settings and is ready for finetuning and evaluation. The next phase targets model finetuning and testing, with three practical challenges: limited datasets with hierarchy labels, realism gaps in synthetic data, and limited compute for scaling data and finetuning. Even with these constraints, we expect a hierarchy-tuned model that reduces injection attack success while preserving benign task-following behavior and keeping over-refusal low.
